# Дерево из карточек

```bash
python3 tree/build_tree.py && python3 tree/build_html.py && open tree/tree.html
```

- `build_tree.py` читает `persons/*.md` (front matter + раздел «## Родство») → `tree.json` и GEDCOM
  (имя файла в `config.json`, поле `ged`). GEDCOM загружается на MyHeritage и GEDmatch.
- `build_html.py` собирает самодостаточную страницу `tree.html`: родословная заявителя на 5 поколений,
  все семьи по линиям, цепочки вглубь, поиск. Статус каждого человека совпадает с его карточкой.
- `config.json`:
  - `root` — ключ карточки заявителя (имя файла без `.md`), **обязательно заполнить**;
  - `root_name`, `root_name_gen` — имя в именительном и родительном падеже («Анна», «Анны»);
  - `family`, `places` — заголовок и подзаголовок страницы;
  - `lineP`, `lineM` — ключи людей, которых считать папиной/маминой линией, если автоматически
    не выводится из родства (обычно пусто);
  - `empty` — подписи для пустых клеток родословной: `{"<ключ>:f": "Антон — отец (имя из отчества)"}`.

Как скрипт понимает родство: в карточке ребёнка строка `- Родители: [[отец]], [[мать]]`
(пол берётся из `sex` карточек), либо в карточке родителя `- Дети: [[...]]`. Супруги без детей —
`- Супруг(а): [[...]]`. Ссылка на несуществующую карточку даёт пунктирную заглушку «карточки нет».

Страница для родни с печатью в PDF (`build_share.py` в первом проекте) сюда не перенесена: при надобности
скопировать и заменить `ROOT` на ключ из `config.json`.
