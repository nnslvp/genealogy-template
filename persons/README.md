# ПРАВИЛО ПРОЕКТА: один человек — один файл

## Суть правила
**По каждому человеку заводится отдельный файл в этой папке.** Туда складывается
вся информация именно о нём: факты, источники, родство, открытые вопросы.
Сводное дерево (в том числе GEDCOM) строится потом **из этих файлов**, а не вместо них.

Почему так, а не одним общим файлом: данные приходят кусками, из разных источников,
часто противоречивые. Когда всё в одном месте — теряется, кто что подтвердил.
Когда по файлу на человека — видно, что по нему доказано, а что нет.

## Правило 1а: карточка на КАЖДОГО найденного человека
Не только на прямых предков. Как только в любом источнике всплывает родственник — брат/сестра прадеда,
его жена, дети, свойственники, односельчанин с нашей фамилией из соседнего гнезда —
**сразу заводится файл**, даже если известно одно имя и один источник. Цель — потом собрать максимально
подробное дерево как побочный результат поиска документов для легализации. Живых людей заводим
без личных данных сверх того, что они сами опубликовали.

## Второе правило: помечать достоверность каждого факта
| Знак | Значение |
|---|---|
| ✅ | подтверждено документом, указан источник |
| 🟡 | со слов родни или из чужого дерева, документа нет |
| 🔴 | неизвестно |
| ⚫ | проверено по документу, для цели не подходит (например, записан «белорус») |

## Третье правило: у каждого факта — откуда он
Для архивного документа указывать полный шифр: архив, фонд, опись, дело, лист.
Для онлайн-базы — ссылку и номер записи. Для рассказа родни — кто и когда сказал.

## Имя файла
`фамилия-имя-отчество-годрождения.md` латиницей, через дефис.
Например: `ivanov-petr-stepanovich-1899.md`.
Если года нет — без него: `ivanov-stepan.md`. Женщин — под девичьей фамилией, если известна;
иначе `anna-zhena-petr-ivanov.md`.

## Шапка файла (front matter)
```yaml
---
id: P-0NN            # стабильный номер, не меняется
name: ФИО по-русски  # для женщин: Фамилия в браке (девичья) Имя Отчество
sex: M / F
birth: дата или год
death: дата или год
birthplace: место
line: папина / мамина / —
generation: заявитель / родитель / дед / прадед / прапрадед / боковая ветвь
status: v / y / h    # для дерева: v = есть документ, y = со слов, h = гипотеза
priority: (необязательно) ★ пометка важности
---
```

## Структура тела
1. **Кем приходится {{NAME_GEN}}** — одной строкой.
2. **Таблица фактов**: факт, значение, чем подтверждено, статус.
3. **Родство**: родители, супруг(а), дети, братья и сёстры — ссылками `[[имя-файла]]`.
   Скрипт дерева читает именно эти строки: `- Родители:`, `- Супруг(а):`, `- Дети:`.
4. **Национальность** — отдельно, если есть что сказать. Это главное, ради чего всё.
5. **Проверено и пусто** — отрицательные результаты. Экономит время в будущем.
6. **Что делать** — конкретные шаги с адресами архивов и номерами дел.
7. **Материалы** — ссылки на файлы в `docs/` и `findings/`.

Шаблон — `_TEMPLATE.md` в этой папке (скрипт дерева его пропускает).

## Связи между файлами
Ссылки в двойных скобках: `[[ivanov-petr-stepanovich-1899]]`.
Ссылка на ещё не созданный файл — нормально, это отметка «здесь будет человек».

## Куда это ведёт
Когда файлы наполнятся, из них собирается GEDCOM (`python3 tree/build_tree.py`) и загружается
на GEDmatch и MyHeritage, чтобы совпадения по ДНК автоматически сопоставлялись с деревом.
